# Реабилитационные направления — Yandex/YDB

Новые получатели работают через существующий Yandex Cloud Functions/YDB backend
и зашифрованные сообщения PSO2. Изменения таблиц YDB не требуются: роли и группы
хранятся в документах. Не запускайте setup, initialize или bootstrap для обновления.

| Направление | Роли получателей |
| --- | --- |
| `rehab1` — I этап | `rehab1_physician`, `psychologist`, `speech_therapist`, `exercise_therapist` |
| `rehab2` — ОМР, II этап | `rehab2_physician` |

Отправлять могут только действующие `neurologist` и `admin`, с действующим
допуском. В этих направлениях разрешён только `review` с шифрованным содержимым
PSO2: фамилия, комментарий и фото при наличии. Бот, реабилитационные специалисты,
кардиолог и реаниматологи создавать эти сообщения не могут. Ответы в новых
направлениях отключены. Старые ПСО → ОРИТ/кардиолог и их ответы сохранены.

Сервер в одной serializable-транзакции повторно проверяет полный состав
действующих получателей, их допуски и отправителя. Все записи входящих создаются
атомарно, либо не создаётся ни одной. При изменившемся составе клиент получает
`roster_changed`: частичная отправка недопустима. Лимит 25 устройств действует
на каждую реабилитационную группу в целом, включая все специальности I этапа.
Приглашение, одобрение, изменение роли и замена телефона сохраняют этот предел.

Уведомления push не содержат фамилию или комментарий. Их фактический момент
показа зависит от сети и ОС каждого телефона; атомарность относится к созданию
входящих, а не к одновременности системных уведомлений. Бот не обслуживает очередь
реабилитационных push. Ограниченный курсор его общей очереди не даёт новым
направлениям блокировать обработку старых сообщений ПСО. Приложение отправителя
повторяет свою серверную очередь при возврате, появлении сети и раз в минуту
в активном состоянии; без активного отправителя фоновые повторы реабилитационных
push не гарантированы. Запись во входящих сохраняется независимо от push.

Чтобы сохранить совместимость с уже установленным Python-ботом, его directory
не содержит новых реабилитационных ролей. Обновлённые клиенты запрашивают полный каталог подписанным флагом
`includeRehab:true` и проверяют допуски. Старые человеческие клиенты без флага
получают только прежние роли; их работа с ПСО сохраняется. Бот на больничном
компьютере для этого обновления не требуется заменять.

Перед подключением новых специалистов обновите просмотрщик организатора и
неврологов. Специалисты открывают актуальный Yandex-адрес, устанавливают значок,
после чего используют персональное приглашение и подтверждение устройства.
Существующие ключи, устройства и сообщения при обновлении функции сохраняются.

Этот выпуск не мигрирует прежние Supabase SQL-схемы. Их ограничения на старые
роли/группы остаются закрытыми для новых направлений; не публикуйте новый
интерфейс как поддерживаемую реабилитационную систему поверх старого SQL backend.
