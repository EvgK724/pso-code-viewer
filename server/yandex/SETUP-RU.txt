ПСО: Яндекс, этап проверки серверной части

Это новая версия для pso-api, а не архив для больничного Python-бота.
Работающий старый просмотрщик и боты пока не переключаются.

1. Откройте pso-api → Редактор. Загрузите этот ZIP целиком.
2. Среда Node.js 22; точка входа index.handler.
3. Память 512 МБ; таймаут 120 секунд; сервисный аккаунт pso-runtime.
   Сеть оставьте пустой. Постоянные ключи не нужны.
4. Добавьте переменную окружения PSO_SETUP_MODE со значением on.
5. Сохраните версию. Функция должна оставаться ПРИВАТНОЙ:
   не включайте публичный доступ и не назначайте allUsers права вызова.
6. Тестирование → входные данные JSON:
   {"action":"initialize"}
7. Если ok:true, запустите второй тест:
   {"action":"selftest"}

initialize создаёт только таблицу pso_state при её отсутствии и проверяет её
структуру. Существующую несовместимую таблицу не удаляет и не переделывает.
selftest проверяет чтение/запись, откат, срок действия, параллельные транзакции,
получателя и отзыв доступа на вымышленных записях. Рабочие отчёты не читает.
Тестовые записи имеют отдельный случайный префикс, удаляются в конце и имеют
предельный срок 1 час на случай обрыва. Физическое удаление YDB TTL отложенное;
приложение дополнительно проверяет срок в каждой операции.

После обоих тестов отправьте результат. Дальше понадобятся отдельный HTTPS-
адрес API Gateway и подключение организатора на новом адресе.
Не устанавливайте новый адрес врачам и не переключайте бот до проверки
сообщения на двух тестовых телефонах, отзыва доступа и уведомления.

Диагностика SELECT 1, которую вы уже прошли, не проверяет запись и транзакции.
Эта сборка также сама по себе не подтверждает соответствие законодательству.
